Counterfactual XAI 기반 자율비행 시스템 검증

XAI로 객체탐지 성능 저하 원인을 설명하고, 실패 가능성이 높은 환경 조건을 우선 탐색한 자율비행 AI 검증 프로젝트.

2026.03–064인 팀XAI 분석반사실 탐색
문제
환경 변화에 따른 탐지 실패
접근
XAI 영향도를 탐색 순서에 연결
담당
분석 화면·시각화·연구 문서

문제와 중요성

정상 환경에서 성능이 높아도 안개, 저조도, 센서 노이즈가 달라지면 객체탐지 성능은 급격히 낮아질 수 있습니다. 가능한 환경 조합을 모두 무작위로 시험하면 평가 비용이 커지고, 실패 원인도 설명하기 어렵습니다.

핵심 질문

어떤 환경변수가 성능 저하를 일으키는지 설명하면서, 실제 실패 조건을 더 빠르게 찾을 수 없을까?

01 · 캡스톤 프로토타입

MATLAB/Simulink 시뮬레이션, XAI 분석, LLM 기반 반사실 환경 생성과 실시간 모니터링을 연결했습니다.

02 · 후속 연구 확장

YOLOv8과 안개·조도·센서 노이즈를 대상으로 Shapley 영향도와 비실패·실패 경계를 검토했습니다.

해결 접근

모든 조건을 같은 순서로 시험하는 대신, 먼저 성능 저하 원인을 설명하고 그 정보를 다음 환경 탐색에 사용했습니다. 기준 성능 대비 mAP50이 15%p 이상 감소한 조건을 실패로 정의했습니다.

판단과 실행 과정

01 · 설명 가능성

성능 수치만으로는 다음 탐색 방향을 정할 수 없었습니다.

SHAP·Shapley 분석으로 안개, 조도, 센서 노이즈가 성능 저하에 기여한 정도와 우선순위를 계산했습니다.

02 · 탐색 전략

영향도가 높은 변수를 먼저 변화시키는 방향을 선택했습니다.

캡스톤에서는 XAI 결과를 LLM 기반 반사실 시나리오 생성에 연결했고, 후속 연구에서는 환경을 순차적으로 악화시키며 마지막 비실패 조건과 최초 실패 조건 사이를 확인했습니다.

03 · 단계 구분

프로토타입에서 사용한 LLM과 후속 검증 결과를 분리했습니다.

후속 KCI 실험에서는 LLM/DSPy를 구현·평가하지 않았으며 향후 확장 범위로 남겼습니다.

직접 기여

팀 프로젝트 범위

자율비행 시뮬레이션, 객체탐지, LLM 기반 조건 생성과 XAI 분석을 연결한 검증 시스템을 구성했습니다.

제가 직접 담당한 부분은 XAI 구현·시각화와 연구 결과물 정리입니다.

01 · 구현

XAI 전용 브랜치에서 실시간 모니터링이 끊기지 않도록 화면 동작을 수정하고 Streamlit 분석 화면을 구성했습니다.

02 · 시각화

히스토리 분석에 SHAP 기반 환경변수 기여도 도표를 추가했습니다.

03 · 정보 연결

XAI 결과를 주요 성능 저하 요인과 다음 환경 조건을 정하는 정보로 구조화했습니다.

04 · 문서화

KCC 캡스톤 논문과 최종 논문·포스터·결과보고서를 수정하고, KCI 원고의 요약·제안 방법과 표·그림의 영문 표기를 정리했습니다.

결과와 의미

TTFF는 탐색 시작 후 최초 실패 조건을 발견하기까지 걸린 시간이며, 작을수록 빠르게 실패 조건에 도달했음을 뜻합니다.

제안 방식은 Random 탐색보다 최초 실패 조건을 빠르게 발견했습니다. 이는 XAI 정보를 탐색 순서에 활용할 가능성을 보여주지만, 후속 연구에서 다른 순서 대비 탐색 효율의 우수성을 검증한 결과는 아닙니다.

후속 검증

독립시험 10개 중 최상위 환경변수 일치 6개, 판정 불가 3개, 불일치 1개였습니다. 판정 가능한 7개 중 6개에서 최상위 변수가 일치했고, 두 개발시험에서 진행도 0.9와 1.0 사이의 비실패·실패 조건쌍을 확인했습니다.

검증 범위 — 사전 기준인 7개 이상의 명확한 일치에는 도달하지 못했습니다. Shapley 순서의 탐색 효율과 다른 순서 대비 우수성은 검증하지 않았습니다.
